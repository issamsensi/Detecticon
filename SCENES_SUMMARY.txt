DETECTICON - PHASER SCENES SUMMARY
=================================

Source: src/client/game/scenes/
Canvas: fixed 360x640, FIT scaling, pixelArt on (mobile-first / phone-sized post).

BOOT / FLOW
-----------
main.ts fetches today's puzzle + game state, creates the Phaser game with
PreloadScene, then starts it with that data.

Typical flow:
  PreloadScene -> IntroScene -> TestimonyScene -> AccuseScene -> ResultScene
  AccuseScene <-> CaseFileScene (paged case review, Close returns to Accuse)

Re-entry rules (handled by reload.ts / applyTodayData):
  - finished state                 -> ResultScene
  - attempts used or eliminations  -> AccuseScene
  - fresh state                    -> IntroScene

Optional branches:
  IntroScene  -> LeaderboardScene / CreditsScene
  AccuseScene -> CaseFileScene -> AccuseScene (with same state)
  ResultScene -> LeaderboardScene
  LeaderboardScene / CreditsScene -> back to the scene they came from

SCENE-BY-SCENE SUMMARY
----------------------

1. PreloadScene
   - Loads character sprites + detective sprite; missing files are logged and
     ignored (colored fallback rectangles are used instead).
   - On create, calls applyTodayData(), which registers all other scenes and
     routes to the correct starting scene based on saved state.

2. IntroScene
   - Case cover: Inspector Quill sprite, puzzle title, scene description.
   - Buttons: "Start", "Weekly ranking", "Credits", small "?" (help).
   - "How to play" overlay: 3 numbered lines + "Got it"; shown once per logged-in
     user (Redis detecticon:seen-howto:{player}) and every time when logged out.
     The "?" button reopens it. A full-screen shade blocks the buttons below.
   - Start resumes an in-progress game in AccuseScene if attempts were already
     used or the case is finished; otherwise it goes to TestimonyScene.

3. TestimonyScene
   - Plays the 4 suspects' testimonies one at a time with a typewriter speech
     bubble anchored above each pixel portrait; portrait animates while talking.
   - Shows "Suspect N of 4" counter, name/role plate, and a blinking
     "tap to continue" hint.
   - Tap behavior: first tap skips the typing; next tap advances to the suspect;
     after the last testimony, starts AccuseScene.
   - Layout constants keep the bubble from overlapping the counter.

4. AccuseScene
   - Lineup of remaining suspects (64px sprites, first name labels) with an
     "Attempts left" HUD and tap targets.
   - Accusing calls the server accuse() API:
       * correct          -> reveal bubble with the contradiction, then ResultScene.
       * wrong, attempts  -> bubble with that suspect's alibiProof, suspect is
                            removed from the lineup, player taps to continue.
       * wrong, no tries  -> reveal culprit, then ResultScene.
   - Bubble has an upward tail pointing at the accused suspect. Tap skips the
     typewriter, then taps again to confirm the pending action.
   - Handles login (401), state sync (400/404 -> reloadToday), network errors,
     and tap-to-retry; blocks duplicate taps while a request is in flight.

5. CaseFileScene
   - Opened by the "Case file" button in AccuseScene (placed above the lineup
     and below the attempts HUD).
   - Page 1: scene text + suspects 1-2; page 2: suspects 3-4. Each entry shows
     name, role and testimony at 12px.
   - Cleared suspects are marked "CLEARED" and show their alibi proof, read from
     state.eliminatedAlibis (server-provided, eliminated suspects only).
   - Prev/Next and an always-visible Close button; no masks or drag-scrolling.
   - Close returns to AccuseScene with the same puzzle and state.

6. ResultScene
   - Shows solved/closed status, attempts used, culprit name, points earned,
     and the shareable result text (e.g. "Puzzle #12 :red_square:...").
   - Compact bar chart from /api/stats/today: solved in 1/2/3 tries and failed,
     with counts and total players. The player's own bar is highlighted. Hidden
     quietly on fetch error or zero players.
   - Live countdown to the next puzzle (UTC midnight), cleared on shutdown.
   - "Weekly ranking" button opens LeaderboardScene.
   - "Post to comments" shares the result once per player per puzzle, with a
     two-tap confirmation/cancel flow; handles 401, 409 (already posted), and
     network errors. No copy button (clipboard unavailable in the webview).

7. LeaderboardScene
   - Fetches the weekly (UTC) leaderboard: top entries with rank, username and
     points; the current player is highlighted, including when outside top 10.
   - Shows week id, "Loading..." / error states, and a reset countdown.
   - "Back" returns to ResultScene or IntroScene depending on entry point.

8. CreditsScene
   - Shows compact credit pages from shared/credits.ts with Prev/Next pagination
     and a page indicator (pagination used instead of drag-scrolling so the Back
     button and panel never overlap on a phone).
   - "Back" returns to IntroScene.

SHARED UI HELPERS USED BY SCENES
--------------------------------
- ui/backdrop.ts  - interrogation-room background (simple/full variants).
- ui/Character.ts - pixel character with fallback rect + talking animation.
- ui/text.ts      - wrapped text blocks and auto-sizing typewriter speech bubbles.
